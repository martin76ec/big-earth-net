# Project Implementation Guide: Self-Supervised Image Classification using I-JEPA

## Overview
This project leverages the **Image Joint-Embedding Predictive Architecture (I-JEPA)** to perform feature extraction on unstructured image data. Given the availability of an NVIDIA H200 GPU, the project utilizes high-capacity Vision Transformers (ViT) to process complex imagery. The chosen dataset for this implementation is **BigEarthNet-S2** (multispectral satellite imagery), which provides sufficient complexity to demonstrate the advantages of self-supervised representation learning.

## 1. Introduction
The documentation must begin with an introduction that clearly motivates the problem to be solved (e.g., automated land-cover classification from satellite imagery) and justifies its practical and academic importance.

## 2. Exploratory Data Analysis (EDA)

## 3. Feature Extraction (I-JEPA Implementation)
Because the dataset consists of unstructured data (images), a robust feature extraction phase is required.
* **Architecture:** The project shall implement a simplified I-JEPA model. 
* **Mechanism:** A Context Encoder (based on a Vision Transformer) must be trained in a self-supervised manner to predict the latent representations of missing image patches based on context patches.
* **Hardware Utilization:** The massive VRAM and compute of the NVIDIA H200 shall be utilized to train a large ViT backbone with a high batch size, ensuring stable self-supervised convergence.
* **Output:** The trained context encoder will be frozen and used to extract fixed-size embeddings for all images in the dataset.

## 4. Feature Selection
According to the project guidelines, since the problem involves unstructured image data and deep learning feature extraction (transfer learning/self-supervised learning), traditional filter-based feature selection may be omitted. However, an analysis of the variance within the extracted latent dimensions may be included as supplementary validation.

## 5. Hyperparameter Optimization
The extracted embeddings must be passed to a downstream classifier.
* **Technique:** Hyperparameters (specifically the regularization parameter, $\lambda$ or $C$, of the Logistic Regression model) must be optimized.
* **Validation:** A repeated k-fold cross-validation strategy shall be employed. 
* **Tools:** The use of **Optuna** is highly recommended to search the hyperparameter space efficiently.
* **Deliverables:** The final report must present a plot of the lambda optimization process and a learning curve demonstrating model performance across epochs or data sizes.

## 6. Statistical Comparison of 2 ML Techniques
A rigorous statistical comparison must be executed between two distinct approaches. 
* **Model A (Proposed):** I-JEPA Feature Extractor + Regularized Logistic Regression.
* **Model B (Baseline):** Standard pre-trained CNN Feature Extractor (e.g., ResNet-50) + Regularized Logistic Regression.
* **Validation Protocol:** Both models must be evaluated using a **10 repetitions with 10 folds (k=10)** cross-validation setup. The H200 GPU will be instrumental in executing these 100 fits within a reasonable timeframe.
* **Hypothesis Testing:** A non-parametric test, such as the **Wilcoxon signed-rank test**, must be applied to the cross-validation scores to determine if there is a statistically significant difference in performance between the two feature extraction methods.
